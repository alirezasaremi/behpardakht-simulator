# Behpardakht Simulator v0.1.0

Proposed release notes. `v0.1.0` is not published until human approval, tag creation, and any chosen release action.

## Purpose

First local-only development/test release for selected Behpardakht Mellat payment-gateway flows. Independent, unofficial software; not affiliated with, endorsed by, or certified by Behpardakht Mellat.

## Highlights

- Local `bpPayRequest`, normal-path `bpDynamicPayRequest`, and normal-path `bpCumulativeDynamicPayRequest` return documented normal `0,RefId` shapes.
- Fake local StartPay/Sale page, controlled callback dispatch, Verify, Settle, and combined VerifySettle support practical merchant-flow testing.
- Safe dashboard, deterministic semantic scenarios, and bounded one-shot transport faults support diagnosis and failure-path tests.
- Source-grounded protocol records, uncertainty ledger, validation coverage, and security boundaries establish release foundation.

## Supported operations

`bpPayRequest`, `bpDynamicPayRequest`, `bpCumulativeDynamicPayRequest`, `bpVerifyRequest`, `bpSettleRequest`, `bpVerifySettleRequest`, plus structural/correlation handling for `bpInquiryRequest` and `bpReversalRequest`.

## Safety model

Use synthetic local data only. Never send real PAN, PIN, CVV2, OTP, banking credentials, secrets, or production callback data. Callback delivery is disabled until an exact controlled-origin allowlist is configured. No real funds, banking action, settlement, or deposit occurs.

## Known limitations

- Local SOAP profile is not claim of provider WSDL or production wire compatibility.
- Inquiry/Reversal calls safely Fault instead of inventing unsupported provider results.
- No merchant authentication, persistence, callback retries, automatic timers, Refund, Charge, payout/provisioning, or production deployment behavior.
- Dynamic/Cumulative later lifecycle reuse is explicitly limited local `DERIVED` compatibility; no payout or distribution semantics are modeled.
